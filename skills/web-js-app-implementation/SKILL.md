# 网页 JS 逆向直连数据抓取技能

- 本文件是技能的唯一权威版本：执行过程中对规范、踩坑、接口参数的任何更新，必须同步回写本文件（见「技能文档同步更新规则」），禁止只留在对话上下文或临时文件中。
- 若本文件在目标机器上不存在，执行前先向用户确认文件当前位置，并回写更新本文件中的路径。

## 定位

面向任意网页后台（客服系统、电商平台、商家后台等）的结构化数据抓取。Agent 通过 JS 逆向与接口直连完成取数，用户只负责提供目标页面、筛选条件与辅助操作（影刀流程 / 登录态）。

## 核心原则（强制）

1. **JS 逆向 / 接口直连**：必须通过逆向页面 Network 请求、直接调用业务接口取数。禁止模拟人工操作（禁止 browser-agent 点击页面、禁止 UI 自动化采集）。
2. **token 自动化**：token 通过影刀执行 JS 从页面存储读取后传参，或通过 CDP 连接调试浏览器自动读取。禁止要求用户手动从 Console 复制。
3. **一次成型**：动手前先确认需求全面性，确认后交付可用脚本并自行验证，反对反复试错式交付。
4. **输出即用**：输出给影刀的 result 只传二维列表 / 字典，符合影刀参数格式，不附加无关内容。

## 执行前必问清单

- 数据范围：哪些业务模块、每模块的筛选条件（时间区间 / 部门分组 / 关键词 / 分页）。
- 输出结构：二维列表（表头行 + 数据行）还是字典列表；是否带合计行。
- 合并约定：多模块数据合并方向（横向延长列 vs 纵向追加行）、表头与合计行组织方式。
- token 来源：影刀传参 / CDP 自动读取 / 缓存复用。
- 交付物：脚本路径、运行验证结果。

## 技术路径

1. **逆向定位接口**：打开目标页，Network 面板筛选 XHR/Fetch，定位数据接口；必要时从前端 chunk/JS 源文件中提取接口路径与列字段映射（搜索接口关键词即可定位）。
   - **辅助手段（可选）**：陌生站点或需登录后才能看到数据时，可选用 browser-use 类 AI 浏览器自动化框架，自动完成登录、设置筛选条件、翻页等操作，以便观察接口完整请求参数。仅作逆向观察辅助，严禁用其逐项点击页面取数。
2. **还原请求**：确认请求方法、URL、Query/body 参数、必要请求头（token 注入方式、Origin、Referer、Cookie、语言时区等）、分页参数、响应结构（列表字段、合计字段、分页元数据、成功码判定）。
3. **获取 token**：优先影刀执行 JS 读页面存储（sessionStorage / localStorage / cookie）传入；或 CDP 连接调试 Chrome 执行 JS 表达式读取。实现本地缓存 + 过期检测（如 JWT exp）避免重复取。
4. **本地直连验证**：用脚本补全 headers 直连接口，与页面数据逐项核对（数量、合计、字段值）。
5. **编写脚本**：分三层——配置区（站点域名、接口清单、列定义、token 表达式）、通用模块（依赖自装、请求封装、分页拉取、清洗、表格构建、token 管理）、业务函数（薄封装取数 + 清洗 + 组表）。
6. **验证交付**：运行脚本核对输出长度、列数、关键值符合约定后交付。

## 通用能力要求

以下能力 Agent 自行实现（不限定语言与代码格式，需适配影刀内置 Python 环境，如 3.7 / 旧版 pip 的兼容处理）：

- 依赖自动安装（兼容系统级 Python 的 PEP 668 保护与旧版 pip）。
- 统一请求头构造：token 注入、Origin/Referer 等防跨域头补全。
- 分页拉取：按总页数 / 游标循环取全量，避免只取第一页。
- 响应校验：成功码判定；将"业务失败码（如 999998）"视为 token 失效信号，自动清缓存重取并重试一次。
- 数据清洗：HTML 标签与实体剥离、时间戳（毫秒/秒）格式化、嵌套消息对象文本提取。
- 表格构建：按列定义生成二维列表（表头行 + 数据行 + 可选合计行）；支持多模块横向延长合并（表头追加列、数据行按位补值）。
- CDP 浏览器管理：调试端口探测、独立 user-data-dir 启动调试实例、优雅关闭；动用户 Chrome 前必须提示风险。
- **Chrome 可执行文件自动探测（换电脑零配置）**：脚本顶部配置区 `Chrome路径` 留空时自动探测，顺序为：显式配置路径 → 注册表 App Paths（`HKLM`/`HKCU` 的 `...\App Paths\chrome.exe`，覆盖自定义安装位置）→ 常见默认路径（Program Files / Program Files (x86) / LOCALAPPDATA）；全部未命中再报错提示手动填顶部变量。禁止在脚本里写死单一路径。

## 输出规范

- result 只传二维列表 / 字典。
- 用户指定固定长度的表（如"长度 2 = 表头 + 合计"）时必须严格保持；新数据按列横向延长，不纵向追加成多行。
- 日期类字段统一 **YYYY-MM-DD** 格式：有日期选择框的页面一律提供"开始时间 + 结束时间"两个变量（如 `开始时间 = "2026-08-24"`、`结束时间 = "2026-08-24"`）；接口若要求紧凑格式（如抖店 startTime=20260824），脚本内部自动转换，用户侧只见 YYYY-MM-DD。
- **交付脚本必须同时输出请求结构**：向用户交付脚本时，须在回复中给出实际请求的完整 URL + 查询参数结构（method / URL / query 参数 / 分页参数），便于用户核对与复用；脚本运行 stdout 的 JSON 中也要带 `request` 字段（本次实际发起的第一条请求 URL）。
- **脚本顶部必须设可配置变量区**：脚本最顶端用醒目注释块提供本次取数核心变量（如抓取日期、抓取分组、端口、页大小），用户改变量即可执行，不要求改业务代码；命令行参数仅作覆盖项，默认值必须取自顶部变量。

## 脚本结构规范（三层模板）

1. **顶部配置区**：全中文变量命名，备注必须**一行式精简**（每个变量一行短注释）；日期用**开始时间 + 结束时间**两个变量（YYYY-MM-DD，留空默认昨天 / 等于开始时间），接口格式由脚本内部转换；Python 3 支持中文标识符，无需为兼容性退回英文名。命令行参数仅作覆盖项，默认值必须取自顶部变量。**禁止长注释块**：影刀魔法指令复制粘贴时，超长/多行中文备注会导致无法识别（实测踩坑）。
2. **通用模块**：CDP 客户端、请求封装、分页拉取、行映射构建（含不同分组的表头与字段映射分支）。
3. **业务函数**：`fetch_staff_table(date, query_type, port)` 返回二维列表 + 请求 URL；`main` 解析命令行覆盖顶部变量并输出 JSON。

## 分组维度确认规范

- 逆向接口的分组/筛选参数（如抖店 `queryStaffData` 的 `queryType`）必须实测可选值后再固化到脚本与文档：`queryType=1` 按客服（每行一名客服）、`queryType=2` 按客服分组（每行一个分组，含 `staffGroupName` / `staffGroupCount`），其余值返回业务错误码即不可用。
- 不同分组维度表头不同：按客服含"账号"列；按分组含"分组、客服人数"列，字段映射 `staffGroupName`、`staffGroupCount`。

  |---------|---------|------|
  | 全店 | （不传 groupId） | 默认全部客服 |
  | 售前客服 | 9878 | |
  | 售后客服 | 146284 | |

## 登录态保全与调试实例规范（Chrome 127+/136+/151 实测）

1. **Chrome 127+ 全面启用 v20（App-Bound Encryption）加密 cookie**：cookie 只能由 Chrome 进程自身解密，外部程序（DPAPI+AES-GCM 直读 SQLite）一律失败。**严禁复制 / 重命名 / junction 指向原 profile 来"保留登录态"**——profile 路径或完整性变化后，Chrome 拒绝解密 cookie，登录态清空（接口返回 code 10005 登录过期）。
2. **Chrome 136+ 安全限制**：user-data-dir 为默认路径（含显式传入默认路径）时，`--remote-debugging-port` 被强制忽略。无法用已登录的默认 profile 直接开调试端口。
3. **唯一可靠取数路径**：
   - 启动独立 user-data-dir 调试实例：`--remote-debugging-port=9222 --remote-allow-origins=* --user-data-dir=<非默认路径>`；
   - 请用户在调试实例内扫码/账号登录一次（抖店扫码无法 AI 替代，需明确告知用户这是唯一一次人工操作）；
   - 登录后立即用 CDP `Network.getAllCookies` 由 Chrome 自身解密导出全部 cookie 存 JSON 永久缓存；
   - 后续取数：启动独立调试实例 → `Network.setCookies` 注入缓存 cookie 恢复登录态 → 导航目标页 → 接口直连。
4. **动用户浏览器前必须提示风险**；优先探测 9222/9223 是否已监听；已登录浏览器无调试端口时，不要无谓重启。
5. **browser-use 定位**：底层 Playwright/CDP，连接现有浏览器仍需调试端口，自启实例为空白登录态，无法绕过 ABE 与默认路径调试限制；仅作逆向观察辅助，严禁替代取数。

## 抖店登录与选店规范（实测 2026-08-24）

1. **登录页真实地址**：`fxg.jinritemai.com/login/common`。`im.jinritemai.com` 根域是宣传页，未登录访问工作台 URL 不会重定向到独立登录页，而是直接渲染页面并提示"登录过期，请重新登录"——模拟登录前先定位页面内登录触发点，或直接导航到登录页。
2. **邮箱登录（无验证码，更优方案）**：登录页切"邮箱登录"tab，邮箱+密码直登，无短信验证码环节，可全自动完成（实测 WAN_2003@126.COM 成功）。表单元素定位：邮箱输入框 `placeholder="请输入邮箱"`、密码输入框 `input[type="password"]`、登录按钮。脚本顶部配置区新增 `登录账号` / `登录密码` / `登录店铺` 三个变量。
3. **登录后选店（多店铺账号）**：若出现"请选择店铺"页，店铺卡片为 `div[class*="roleItem"]`，React 事件绑定在元素上，`el.click()` 不触发跳转，必须用 CDP `Input.dispatchMouseEvent` 按真实坐标点击。
4. **登录态判定时机**：`currentuser` 接口在未选店前返回 code=10005（即使账号已登录并显示店铺列表），选店后才 code=0 且 `data.ShopName` 显示店铺名。判定"已进入目标店铺"必须等选店动作完成后，再取 currentuser 确认 ShopName 匹配目标店铺（如"352官方旗舰店"）。
5. **取数完毕清理（安全规范）**：请求完毕后执行"退出登录并清理"三步：`Network.deleteCookies` 清抖店域会话 cookie → `Page.reload` → `Page.close`；只清浏览器会话 cookie，不动本地缓存 JSON。下次取数仍先注入缓存，缓存失效才触发邮箱重登。

## 登录滑块验证应对规范（实测 2026-08-24）

- **现状**：抖店邮箱登录实测无验证码（账号密码直登），正常不经过滑块环节。
- **触发条件**：全新调试实例首次登录（无指纹积累）、登录/登出过于频繁、IP 异常（代理/机房/频繁切换）、短时间内反复失败重试。
- **避免优先级**：① 缓存 cookie 优先注入（能不登录就不登录，自然无滑块）；② 首次登录人工一次并导出永久缓存；③ 固定 user-data-dir 积累指纹；④ 自动登录时模拟人工节奏（输入/点击间隔随机化）；⑤ 控制登录频率，避免频繁"清 cookie 退出登录 → 重登"。
- **兜底策略（脚本层，已实现）**：登录提交后轮询循环内检测验证码特征（`iframe[src*="captcha"/"verify"]`、`tcaptcha`、`div[class*="captcha"]` 等，且尺寸 >50px 才算可见）→ 优先**自动过滑块**：`自动滑动验证码()` 定位拖拽按钮（`#tcaptcha_drag_button` 等）→ 读缺口位置（`#slideBlock` 初始 left 即缺口偏移）→ CDP `Input.dispatchMouseEvent` 拟人轨迹拖动（先快后慢 + 随机微抖 14~22 段）→ 等待校验；跨域 iframe（如 verify.snssdk.com）无法读内部坐标或点选类验证码，自动方案不可用 → 打印提示人工完成 → 人工完成后验证码元素消失自动继续登录流程。顶部 `自动过滑块` 变量可关闭；检测到验证码禁止硬刚重试，连续失败会加重风控。登录等待秒数不足时手动完成可能超时，可调大顶部 `登录等待秒数`。

## 踩坑要点

- 分组维度别靠猜：接口分组参数（queryType）需逐个实测可用值并固化，避免把"业务错误码"当成交互参数。
- 交付脚本的顶部配置区备注要**一行式精简**：超长/多行中文注释复制进影刀魔法指令会无法识别（实测），中文变量名本身无碍，长注释才是问题。
- 日期配置统一 **YYYY-MM-DD 区间（开始时间/结束时间）**：不要让用户在脚本里填接口紧凑格式（如 20260824），由脚本内部转换（`接口日期()` 兼容两种输入）；同时保留旧参数兼容（如 `--date` 等价于起止同一天）避免影刀旧流程挂掉。
- 多分组结果合并时注意展平：循环多个分组抓取时若把每组"行列表"整体 append，合并去重会只保留第一组（嵌套列表被当成单行），必须 extend 展平后再去重。
- 分组筛选参数名别靠猜：抖店实际用 `groupId`（如 146284），`staffGroupIds`/`staffGroupName`/`groupName` 等猜测参数均不生效（返回全部数据而非筛选结果）；分组编号须从页面下拉逐个选择后抓包获取。
- 交付脚本时若不输出请求结构，用户无法核对与复用；请求 URL 与参数必须随交付给出。
- token 本地未过期但服务端失效（业务失败码）→ 需兜底重取。
- 逆向列定义优先从前端 chunk 找字段映射，再与 Network 响应逐列核对，避免猜字段名。
- 合并结构理解偏差 → 开工前确认方向，默认按用户偏好横向延长。
- 分页接口需确认总页数 / 合计对象，防漏数据。
- 交付前必须自行运行验证，不能只贴代码。
- cookie 保存时机：必须在可驱动浏览器（调试实例）登录成功后立即导出，保存到独立 JSON 并本地缓存；禁止从无效副本导出后误报"已保存"。
- 登录后未选店前 `currentuser` 也返回 code=10005，别把"已登录但未选店"误判为登录失败；选店动作完成后再判定登录态。
- 多店铺账号选店页卡片是 `div[class*="roleItem"]`，CDP 必须用 `Input.dispatchMouseEvent` 真实鼠标事件点击，`el.click()` 不触发 React 跳转（实测）。
- 抖店邮箱登录无验证码、账号密码直登，比手机号+短信验证码更快更稳，优先邮箱登录；登录页为 `fxg.jinritemai.com/login/common`。
